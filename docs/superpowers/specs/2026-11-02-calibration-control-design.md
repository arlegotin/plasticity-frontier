# Calibration control verification without aggregate report parsing

This is a builder proposal for a bounded internal resource refinement under sections 9–11 of the approved [full-program design](2026-11-01-plasticity-frontier-design.md) and the user's instruction to continue when a clear improvement path exists. It preserves the specified maps and gates. This document is not a new user-approved scientific claim or an assertion that implementation has passed review. The accompanying plan contains one source task; no scientific execution is part of this refinement.

## Evidence and purpose

The retained `.superpowers/sdd/2026-11-02-full-campaign-execution/g9-capacity-probe-report.md` and durable [capacity readiness record](../../results/2026-11-02-full14-capacity-readiness.md) record 14 actual complete workers on source `0e4f63adbfa502c3e53a6e0afa44e34d8057a3db`, all exit 0, tuning resolved and equality passing, at capacity-only T=V128/N2048 on a known excluded exploratory root. The resource array is 11,536,257 bytes; the measured actual14 whole-control projection is 11,655,683 bytes. The unchanged replay guard estimated 6,034,831,232 bytes: admitted at the later 7,450,238,976-byte half reserve, above the initial 5,429,411,840-byte half reserve. The conservative full-control forecast was 11,263,245,616 bytes and lacked affordable replay admission. The complete balanced196 calibration/fixed pipeline remains unrun; this is not an actual failed G9 or proof that the full coordinator will fail. The later documentation-only commit does not change the probe's executed source.

`benchmark_methods` keeps a complete first resource/selection ledger per method and publishes the aggregate `benchmark.json` with `_atomic_json`. `finalize_benchmark_manifest(calibration_path, manifest_path, campaign_output)` decodes that aggregate, validates it and freezes its `records.content_hash`, identity, configuration, conditions, selected hashes and timing schedule. `validate_campaign_manifest(manifest, *, manifest_path=None)` currently decodes it again.

In reporting, `_input_paths`, `_raw_files`, `_guard_inputs` and `_benchmark` treat the aggregate as semantic JSON. `_benchmark` decodes it only to check `content_hash`, discards it, then reads calibration `inputs.json` and complete raw workers to rebuild `_fixed_schedule`. Campaign rows, selected hashes, conditions, equality, completeness and comparisons continue to come from workers. `_replay._replay_benchmark` calls that reconstruction, verifies requests and compares full worker pairs. The aggregate's 256× semantic allowance, doubled at replay admission, is unnecessary for a verified byte-only reader, but simply deleting it or substituting an unrelated byte hash would weaken integrity.

## Approaches

1. **Canonical full-control sidecar from the public finalizer — recommended builder choice.** Export the entire parsed object in the exact encoding used by `content_hash`. Freeze a versioned sidecar reference and the original file's byte hash. Reporting verifies both files by streaming SHA-256 and retains their complete inventory without decoding either. Finalization/validation still perform their native semantic checks. This changes neither producer output nor scientific reconstruction.
2. **Compact control plus complete raw references.** Move schedule/identity summaries into a small versioned control and retain full historical control/worker references. This could also reduce finalizer memory, but changes producer/control schemas and requires a broader proof that selected summaries match the complete records, including unknown fields. It is unnecessary for the measured report-only aggregate bottleneck.
3. **Streaming JSON parsing/canonicalization at reporting time.** Verify the existing semantic hash without a sidecar. Sorted object keys, complete unknown-field coverage and exact Python JSON number/string encoding require substantial parsing/sorting machinery or temporary storage. This adds complexity and potentially dependencies for no present scientific benefit.

Only approach 1 is specified here. It is a prospective optimization, not an already established whole-pipeline capacity result.

## Versioned binding and publication

Keep the public finalizer and validator signatures unchanged. Keep `frozen.calibration_path` pointing at the original immutable calibration file, and keep `frozen.calibration_sha256 = content_hash(evidence)`. New finalizations add exactly this binding:

```json
"calibration_control": {
  "format": "prepared_calibration_canonical_v1",
  "path": "/absolute/calibration/benchmark.canonical.json",
  "source_sha256": "<SHA-256 of the original calibration file bytes>"
}
```

The sidecar path is exactly `calibration_path.with_suffix('.canonical.json')`, in the same directory. Its path is absolute, distinct from the original and checked against that derivation. It has **no** wrapper object, removed fields or trailing newline. Its bytes are UTF-8 of the same native-JSON encoding as `records.content_hash`: sorted keys, separators `(',', ':')`, `ensure_ascii=True`, `allow_nan=False`. Use the standard encoder's `iterencode` on the parsed JSON object, without `to_json_record` or an aggregate serialized string for the export. Parsed JSON already contains native types; unit tests must establish exact byte equality with `json.dumps(to_json_record(evidence), sort_keys=True, separators=(',', ':'), allow_nan=False).encode()` and hash equality with the unchanged `content_hash`, including Unicode, escaping, floats, negative zero, nested and unknown fields. Do not change `records.content_hash`.

Before decoding the original at finalization or validation, use reporting's existing native-parse admission policy: 64× file bytes, 64 MiB base and the live half-available reserve/cap. A local import can reuse `_guard_paths`/`REPORT_PARSE_FACTOR` without moving or copying the policy. The native allowance covers decoding and the existing semantic-hash validation; it does not classify the full control as a semantic report workspace. This adds safe admission to previously unguarded finalizer/validator reads; a refusal raises the existing `ReportingResourceLimit` and must not publish a finalized manifest. Full producer/coordinator retention remains unchanged and requires separate actual resource admission.

The benchmark CLI must handle that newly possible validator resource refusal with nonzero exit and a machine-readable `LOCAL_RESOURCE_LIMIT` decision. It must not create the fixed output directory, alter the frozen manifest or convert the refusal into an implementation failure/traceback; an identical retry after resources improve must remain possible. This narrow CLI edit is required integration for the new native guard.

All existing finalization checks run before publication. Hash original bytes before and after reading/exporting and refuse a changed source. Stream to a unique temporary file, flush/fsync and independently verify its file digest against `content_hash(evidence)` before publishing the sidecar. Never replace an existing final manifest or different sidecar. An existing sidecar may be reused only if its entire bytes hash matches the just-verified semantic hash; otherwise refuse. Publish without clobbering an existing file, then atomically publish the new manifest. A failed export cannot leave an authoritative manifest. An already published, matching orphan sidecar may remain after manifest publication failure and supports the same explicit retry; remove only the call's own unpublished temporary file. Do not alter the original calibration file, raw directory or old manifests.

## Verification and backward compatibility

For a present `calibration_control`, validate its exact known field set, format, absolute derived path and lowercase SHA-256 syntax. A malformed, null, partial or unknown-format binding fails closed; it cannot fall back to legacy. Verify the original byte SHA against `source_sha256` and the sidecar byte SHA against **existing** `frozen.calibration_sha256`, reading bounded binary chunks. Both proofs are required before hash-only treatment. The finalizer establishes the original-object/sidecar equivalence; subsequent original byte integrity and canonical byte integrity preserve it. An unrelated digest is never accepted as semantic identity.

The validator additionally decodes the original after native admission, checks its existing semantic hash and runs all original schedule/configuration/selected-asset/condition/source checks. It also verifies the new binding when present. In reporting, that verified new binding replaces only the aggregate decode/content-hash step; complete calibration and campaign worker reconstruction is unchanged. A different unknown field, a whitespace-only edit of either bound file, missing sidecar, corrupt byte or changed original must be rejected. A semantically equivalent but noncanonical sidecar (reordered keys, pretty printing or trailing newline) also fails its frozen byte digest; reporting never normalizes it or repairs/recomputes the binding. New-format original-byte integrity is deliberately stronger than legacy's semantic-only check before report sealing.

When the key is absent, finalizer consumers/reporting use the original legacy parse/content-hash path and its semantic 256× report admission. Keep existing legacy oversized-calibration rejection tests. An old frozen manifest is never auto-upgraded, rebound or given a newly generated sidecar by reporting. Old source evidence remains bound to its executed source; a new sidecar never changes that identity. Existing benchmark schema version 1 and report schema `benchmark_raw_refs_v2` remain; the additive frozen binding carries its own explicit format version.

## Inventory and resource accounting

Introduce an internal asset iterator with explicit `semantic` and `hash_only` roles. All existing assets default to semantic. Only the two verified calibration-control files of a new-format finalized benchmark receive hash-only treatment. Neither filename extensions nor user-supplied descriptor flags authorize exemption. Reuse that classification at input admission, raw-inventory admission and `_benchmark` admission. `_input_paths` remains a path-only compatibility wrapper, and `_raw_files` includes both controls plus every existing original input/request/block/descriptor asset with full byte SHA proof. The calibration directory is still located by the original `calibration_path.parent`.

Keep total JSON bytes, largest file and file counts inclusive of controls. Add explicit hash-only file/byte and semantic JSON byte/max counters; compute `json_working_bytes` from semantic JSON only. `_guard_inputs` must combine the new semantic working-byte counter, not the old inclusive `max_json_bytes`, so it cannot reintroduce the aggregate at a higher layer. All files retain inventory/path costs. SHA readers use the existing 1 MiB chunk convention within the unchanged base allowance. There is no cohort of retained control objects.

Constants remain **256 semantic JSON / 64 native parse / 64 MiB base / 16 array factor**, with replay's **two copies** and **half currently available RAM**; an explicit cap may only lower the reserve. Worker blocks, requests, raw-pair checks, retained summaries, keys, indices and other report inputs retain their existing charges. A large semantic worker still fails before parsing even if the controls are hash-only. Preserve unknown fields in both full controls and complete worker references. No baseline, candidate, failure, observation, schedule, statistical count or gate is removed.

## Validation, scope and continuation

One implementation task covers canonical byte equivalence, complete unknown-field preservation, source/sidecar tamper and publication failure, strict format/path rejection, legacy compatibility, independent raw schedule/campaign identity checks, report/replay parity and meaningful resource admission tests. A deterministic padded fixture checks retained objects and guard arithmetic without scientific execution; it is technical validation, never balanced calibration evidence. The actual14 unbalanced capacity probe must not be passed to finalization or repackaged as196 observations.

Source scope is `benchmark.py`, `reporting.py`, the narrow benchmark CLI resource-refusal handler, and focused benchmark/report/replay tests. `_replay.py` should need no production change because it already calls the shared report/input paths; review that call graph explicitly. Preserve public signatures, scientific maps, sample counts, locked dependencies and all identity checks. Doctor executable replay mismatch and pilot descriptors without a native kind are separate delivery issues, outside this refinement.

Commit and independently review all source work before any fresh full G6. The old source36 G6 `INSENSITIVE_OR_UNSUITABLE` remains immutable. Subsequent real G6, complete balanced G9 calibration/public finalization/fixed execution, report and clean replay require their own qualified inputs, held clean source identity, audited fresh roots and full wall/RAM/disk admission under the existing execution plan and `g9-execution-handoff.md`. No new root, source count or successful scientific gate is allocated here. Actual full-control/native parse/coordinator memory and downstream retained-object growth remain open measurements.
