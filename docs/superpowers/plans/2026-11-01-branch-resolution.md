# Branch-aware Local Resolution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the discontinuous-selector stopping failure and bound pilot/report/replay retention while preserving fixed-gamma estimators and scientific evidence standards.

**Architecture:** A focused source-only helper adds noneligible branch-envelope diagnostics to otherwise unresolved local comparisons. Pilot aggregates retain compact planning inputs after full publication; reporting/replay retain indexed complete raw workers and bounded live units. Existing estimators, tolerance, ranking, unsupported-family behavior and scientific comparisons remain fixed.

**Tech Stack:** Existing locked Python, NumPy and SciPy; float64 numerical diagnostics; unittest.

**Spec:** `docs/superpowers/specs/2026-11-01-branch-resolution-design.md`, subordinate to the approved full-program design.

## Global Constraints

- Work on the current `main` branch; make meaningful local commits. Do not push, merge, publish or create a worktree.
- Preserve all fixed-gamma estimators, B04's prior-objective branch selection, candidate eligibility, population, endpoints, inference, precision target and resource reserves.
- Preserve tau=`min(left_marginal_loss_se,right_marginal_loss_se)`, independent task units, paired diagnostics, initial interior probes, all fixed-family groups, resource ties, ridge boundaries, failures and refinement caps.
- Extra branch losses/gradients are noneligible resolution probes using the same observed validation tasks. They cannot enter ranking, alter B04's prior-risk branch selection, or enlarge tau.
- Ordinary float64 diagnostics remain `float64_diagnostic`; they are not rigorous enclosures or exact certificates. Fail closed when margins cannot be distinguished from numerical error.
- Version the source policy as `min_marginal_loss_se_branch_envelope_v2`. Historical v1 artifacts keep their identities and unresolved verdicts.
- No protected keys or confirmation before reviewed source, full G6 evidence and a valid freeze. Reused exploratory observations add zero independent preparations.
- Preserve 256-fold semantic JSON expansion, 64-fold native parse protection, 64 MiB base, array/inventory allowances and the half-current-available-memory ceiling. Monolithic calibration remains guarded; confirmation SQLite 8-fold JSON plus 64 MiB disk guard remains unchanged.
- Complete worker semantics remain in verified raw-reference artifacts under explicit `benchmark_raw_refs_v2` exports; historical reports and raw v1 inputs are not rewritten. No benchmark producer-format or dependency changes.

## Review Focus

- A lower-loss unselected branch must never become the eligible incumbent or enlarge tau (Task 1).
- Fixed basis/noise/width/base witnesses, F tail multiplicity, and endpoint/unsampled numerical errors must prevent unsupported or exact sensitivity claims (Task 1).
- Missing/zero uncertainty, failures, underflow and unresolved comparisons must preserve local refinement, hidden-interior/all-family/ridge boundaries and failure/cost evidence (Task 1).
- Full publication must precede detached planning/worker summaries; selected-level envelopes and mixed-input retained state must charge actual live payloads and release prior graphs (Tasks 3–4).
- Unknown raw fields, corrupt/missing/duplicate references, cost-ID alias topology and frozen calibration/asset/order/condition checks must survive versioned export and paired replay (Task 4).

**Proposed interfaces (names and format are decisions for this task):**
- `reporting._retain_benchmark_workers(root: Path, output: Path, *, phase: str, consume: Callable[[dict, dict], None], retained_bytes: Callable[[], int]) -> dict`: reads sorted existing block files one at a time; publishes each complete worker; calls `consume(worker, reference)` synchronously while live; returns only index metadata. `phase` is `campaign` or `calibration`. Consumer must detach retained fields. No generator/closure/list may retain completed blocks.
- `reporting._compact_benchmark_resource(resource: dict, reference: dict) -> dict`: returns detached fields required by current tables/claims plus verified full-resource/selection references, never candidate/probe/array graphs.
- `reporting._benchmark(entry: dict, *, output: Path, emit: Callable[[dict], None] = lambda row: None) -> dict`: returns versioned compact summary; `output` is report package root; `emit` writes adverse records synchronously. Update every direct caller rather than retain an eager compatibility branch.
- `reporting._load_worker_ref(reference: dict, package: Path, *, retained_bytes: int = 0) -> dict`: guard before loading; verify file hash, full worker key and reference counts; reject missing/corrupt files, traversal outside package, duplicate index keys and inconsistent source binding.
- `_replay._run_file(command: list[str], *, cwd: Path, env: dict, stdout_path: Path, stderr_path: Path, log: Path) -> Path`: subprocess stdout/stderr go directly to files; log command/cwd/returncode and path/hash/size references. Retain complete output on failure; parse gate output only after admission; propagate exit-75 `LOCAL_RESOURCE_LIMIT`. Leave small-command `_run` callers unchanged.
- `_replay._benchmark_scientific(worker: dict) -> dict`: exactly the existing resource-field projection and row schedule projection; call `_scientific` once on the complete resource projection with one alias map spanning all nested cost IDs in that worker. Preserve every current field, including complete `selection`; never compare compact summaries instead.

**Versioned output contract:**
- New `tables.json` root and each benchmark summary declare `report_schema_version: "benchmark_raw_refs_v2"`; unchanged input descriptors/raw producer blocks remain schema v1.
- Summary contains `conditions` (detached first-worker value, with existing per-worker/frozen validation), existing rows/status/controls/pareto/inputs, compact resources, and `worker_records_ref: {path, sha256, record_count}`. No `raw_workers` placeholder or silently shortened list.
- `benchmark_workers.json` becomes `{report_schema_version: "benchmark_raw_refs_v2", benchmarks: [{input_id, worker_records_ref, calibration_worker_records_ref?}]}`: an explicit index directory, not an array masquerading as the old raw payload.
- Index `benchmark-input-<input_id>/<phase>/workers.index.json` contains `{schema_version: 1, record_count, records: [...]}`. Each record contains `ordinal`, `worker_key: {block, method_id}`, package-relative `path`, file `sha256`, `source_block_path`, `source_block_sha256`, `source_json_pointer`, and `candidate_count` where that list exists.
- Worker paths use numeric ordinals, not unsanitized method IDs. Each file contains the complete semantic worker unchanged, including unknown fields. Index order records original sorted-block/list order; pairing key uniqueness is independently enforced.
- Per-method resource keeps existing `method_id`, `initialization_norm`, `trainable_parameters`, `runtime_stored_scalars`, `runtime_serialized_bytes`, `execution_hash`, `selected_execution_hash`, `equality_status`, full `risk` (including losses/task keys/uncertainty labels), `memory.isolation`, `memory.peak_rss_bytes`, and `selected_asset.information_access`; preserve missing fields where the old resource omitted them. Full `resource_ref` points at `/resource`; other selected-asset/equality/diagnostic contents remain available there.
- `selection` summary retains existing `selected_id`, `selected_options`, `source_hash`, `validation_hash` when present; `selection_ref` points at `/resource/selection`, and `candidate_records_ref` adds worker key/path/hash, JSON pointer `/resource/selection/candidate_records`, and actual count. Missing fields stay missing; do not synthesize roles or successes.
- All references resolve relative to report/replay package root and are hash-verified. Publish index only after worker files are complete. Partial output never receives a completed/matched receipt.
